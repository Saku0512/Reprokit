# セキュリティ仕様 v0.1.0

> 脆弱性検証環境には意図的に危険なソフトウェアが含まれる。**Dockerは完全な隔離境界ではない**。重要な環境での検証は専用VMと制限されたネットワークを使用する。

## 設計原則

- `create`では第三者のスクリプト、Dockerfile、コンテナを実行しない。
- `start`時にManifest、Lockfile、元ソース、解決済みComposeの整合性を再検証する。
- **拒否を既定動作**とし、v0.1では危険な設定を任意フラグで無理に許可する仕組みを作らない。
- 起動するコンテナイメージは第三者コードであり、digest固定は**改変を追跡できるようにする仕組み**であって安全性の保証ではない。

## Docker Composeポリシー

| 設定・状態 | 動作 |
| --- | --- |
| `privileged: true` | 拒否 |
| `network_mode: host` | 拒否 |
| `pid: host` / `ipc: host` | 拒否 |
| ホストbind mount（read-only含む） | 原則拒否（v0.1では例外なし） |
| Docker/Containerdソケットのマウント | 拒否 |
| `cap_add` / `devices` | 拒否 |
| `build` / Dockerfile依存 | 拒否 |
| `include` / `extends` | 拒否 |
| 外部ネットワーク・不明なネットワークモード | 拒否 |
| 未固定の外部環境変数/`env_file`/外部ファイル | 拒否 |
| 明示的`command`/`entrypoint` | v0.1では拒否 |
| rootユーザー | 警告（拒否ではない） |
| `restart` による自動再起動 | 無効化して実効構成に固定 |
| 公開ポートの0.0.0.0/IPv6/外部IP | 拒否。IPv4 `127.0.0.1`のみ |

未知のCompose機能や未知のサービスオプションは誤解釈せず、解析不能なら実行しない（fail-closed）。危険な権限がなければ安全である、と評価するものではない。

## 取得時の安全性

- Git URLはHTTPSのみ。接続先・リダイレクト・資格情報・プライベートアドレスへのアクセスなどを検証してSSRFを防ぐ。
- 固定したGitコミットが目的のリポジトリに存在することを確認する。
- Manifestおよび取得ファイルは長さ・型・サイズを制限して扱う。YAML重複キーや不正なエイリアスを拒否する。
- パストラバーサル、絶対パス、シンボリックリンクを使ったワークスペース外への書き込み・参照を拒否する。
- コンテンツハッシュは**バイト単位**で計算し、起動前に再照合する。

## ホスト環境の前提

- Docker Engine/Composeのバージョンを確認する。localhost公開の既知の問題を避けるため、v0.1ではDocker Engine **28.0.0以上**を動作前提とする（その他の互換性は実機テストで決定する）。
- 制御できない外向き通信やコンテナ脱出リスクまでCLI単体では解消できない。
- 高リスク検証は**専用VM、通信制限、共有資産なし**で行う。

## 運用

ユーザー所有または明示的な許可のある検証環境に限定する。取得時に信頼性や脆弱性の再現可能性を保証する表示を行わない。
