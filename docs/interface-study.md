# Reprokit 学習インターフェース — ハイブリッド構成（採用済み）

> **決定：2026-10-14。** 初学者の学習インターフェースは**ローカルWeb UI**、環境管理・検証の共通エンジンは**Go**、CLIも継続して提供する。Webのみ・CLIのみにはしない。以下は実装予定の仕様であり、実装済みではない。

## MVPの主役を変更（2026-10-15）

UI構成はそのまま**ローカルWeb + Go Core + CLI**で確定。新しい優先順位は、[Vulhub上の既存Labを使い、Webで説明→手動PoC→観察→対策まで教える](vulhub-learning-mvp.md)こと。多機能な環境管理ダッシュボードを先に作らない。

**Webの教材画面には、脆弱性を理解するための日本語解説・PoCの操作手順とコピー・期待結果・ヒント・原因/対策を明示する。** PoCの実行は学習者がローカルのLabに対して行い、Web側から任意コードやPoCを無断実行しない。

## 結論

**Webは「学ぶための画面」、CLIは「環境を扱うための操作」、Go Coreは「両者の共通実装」。**

学習の中心は脆弱性を自分で試し、原因と対策まで理解すること。CLIを使えるかどうかを学習の前提条件にはしない。一方、CLIは熟練度の高い学習者や開発者にも使える独立したインターフェースとして保持する。

## アーキテクチャ

```text
                    Reprokit (local installation)
           ┌─────────────────────┴──────────────────────┐
           │                                            │
    Browser / Web UI                              Terminal / CLI
    教材・手順・ヒント                            create / start / stop 等
           │                                            │
           ▼                                            │
    Local Web Server (Go)                                │
    127.0.0.1:<port>                                    │
           └─────────────────────┬──────────────────────┘
                                 ▼
                          Shared Go Core
                     Registry / Lesson / Manifest
                     Resolver / Lockfile / Security
                     Storage / Docker Runtime
                                 │
                                 ▼
                        Local Docker Compose
```

- **Go Core**：Registry、Manifest、Lockfile、セキュリティ検査、環境取得・起動・停止・削除を実装する。WebとCLIで**同じ関数・ルール**を利用し、異なる権限やロジックに分岐させない。
- **CLI**：Go Coreを呼び出す薄いサブコマンド群。Go Web Serverのプロセスを起動しなくても`create/start/stop/delete`等は動く。
- **Local Web Server**：GoでローカルHTTP APIと静的Web UIの配信を担当。Docker起動を含む状態変更はGo Core経由に限定する。
- **Web UI**：初心者の主画面。教材検索・難易度・手順・ヒント・期待結果・原因/対策・環境状態/片付けを扱う。**ブラウザからDockerへ直接接続しない。**
- **Docker Compose**：学習者のローカル環境上で動作。共用インターネットサーバーに意図的に脆弱なLabを起動しない。

Webフロントエンドのフレームワークおよび配布・ビルド方法は**別途選定**。現時点でSvelteKit等を確定したことにはしない。

## 起動と利用体験

```bash
# Web学習画面をローカル起動（新規追加するCLIコマンド）
reprokit ui

# 既存のCLIで環境操作も可能（変更しない）
reprokit search CVE-2021-44228
reprokit create CVE-2021-44228
reprokit start log4j-solr
reprokit stop log4j-solr
```

`reprokit ui`はローカルWebサーバーを`127.0.0.1`の利用可能なポートで起動し、ブラウザへアクセス先を案内（対応環境なら自動オープン）。通常はネット接続なしでもインストール済み教材の表示・環境状態の確認ができる設計。新規教材・依存イメージの取得には通信が必要な場合がある。

`reprokit ui`によって脆弱なLabは**自動起動しない**。教材からの`create`相当の取得も起動を含まず、`start`は学習者が明示的に選択してリスク説明を確認したときだけ実行する。

## 初期Web画面（MVP）

1. **教材一覧**：CVE名だけでなく脆弱性の分類、難易度、前提知識、学べることを表示。
2. **教材詳細**：概要・学習目標・原典リンク・注意事項・環境の必要条件。
3. **環境準備**：Dockerの状態、取得進捗、ソース情報、起動前の公開ポート・権限を確認。
4. **ステップ別演習**：読む → 自分で試す → 観察する → ヒント → 原因と対策。学習者が入力した操作を無断で任意コマンド実行しない。
5. **片付け**：停止・削除の状態、Volume保持の意味を明示。

Web画面の演習が完了したことと、CVEの自動的な再現検証が成功したことは区別する。教育的な振り返り結果は、Bootable/Verifiedなどの技術状態とは別に扱う。

## ローカルWebサーバーのセキュリティ

- APIとWeb画面は**IPv4 127.0.0.1限定**。外部公開設定、リモートホストからの制御、CORSの無条件許可をv0.1では提供しない。
- **Host検証・Origin検証・CSRF対策・ランダムなローカルセッション認証**を適用。DNS rebindingや別サイトからの操作を防ぐ。セッショントークンはAPIのURLパラメータやログに記録しない。
- 状態変更APIはPOST/DELETE等に限定し、アクセス前に明示確認を要求する危険操作を適切に分離する。認証済みでも権限・安全性チェックを省略しない。
- ユーザー入力をOSシェルへ連結しない。Lab/Instanceの固定IDと許可済み操作をGo Coreへ渡す。ブラウザ側から任意のComposeファイルや実行コマンドを直接渡して実行しない。
- APIが既存のManifest/Lockfile/Runtimeチェックを迂回できないよう、CLIと共通実装にする。
- WebコンテンツのXSSにも備え、教材Markdownをサニタイズし、適切なContent Security Policyを設定する。

## 実装順序

1. **Vulhubの互換性を確認した安全なLabを1つ選定**し、対象のCVEに対する日本語教材と手動PoCステップを作る。
2. 対象Labに必要な最小限のGo Core機能（固定取得、安全性検査、明示起動、停止）を作る。
3. `reprokit ui`のWebで「説明→PoC手順→観察→原因/対策→片付け」を通して体験可能にする。
4. CLIとWebから同じCoreを使っていることを検証する。
5. 初学者に1教材を完走してもらい、その後に2～3教材へ増やす。

**UI選定自体は確定。フロントエンド技術、Lessonの厳密なSchema、配布方式・認証トークンの具体的な実装等は詳細設計で定める。**
