# Reprokit 学習インターフェース比較（検討中）

> 2026-10-14時点の**選択肢と推奨案**。教育目的への全面移行は決定済みだが、CLIかWebかの最終選定はまだしていない。

## 比較

| 評価軸 | CLIだけ | Web UIだけ | Web学習UI + CLIエンジン |
| --- | --- | --- | --- |
| 初心者への説明・視認性 | 長文は見づらい | 文章、図、ヒント、進捗が得意 | **両方の利点を活用** |
| 操作・技術学習 | コマンドの勉強にもなる | コマンド知識を必須にしない | コマンドを必要に応じて学べる |
| 導入の簡単さ | CLIインストール、Dockerが必要 | ローカル方式ならWebもDocker/バックエンドが必要 | ローカルUI起動とDockerが必要 |
| 実装負担 | **最小** | UI、API、状態管理 | **最大**だが段階実装可能 |
| 実験環境との統合 | ターミナル・ブラウザの往復が必要 | ガイドと環境を並べて見せられる | 専門操作はCLIに残せる |
| セキュリティ | CLI実行権限の管理 | ローカルWebサーバーを新設するリスク | CLIの検証機構を共通利用して監査可能 |
| 将来の拡張 | 画面に制約がある | 初心者向け学習機能と相性がよい | 学習者・中上級者両方に対応 |

## 推奨（未確定）

**学習者に見せる主画面をWeb、環境操作のコアをGo製CLI／共通ライブラリにするハイブリッド**が初心者向けUXとして有力。

- 学習者：カテゴリ/難易度検索、ステップ解説、ヒント、観察結果、進捗をブラウザで読む。
- 環境の実操作：Registry/Manifest/Lockfile/RuntimeをGoの共通実装に寄せ、WebからもCLIからも使う。
- エンジニア：CLIをそのまま利用可能。教材からコマンド操作へ少しずつ移行できる。

### 実装候補

- **MVP軽量案**：Go CLI + ブラウザで開くMarkdown/静的教材ビュー。Webダッシュボードなしで教材の質を先に検証。
- **主推奨案**：Goローカルバックエンド + 学習用ローカルWeb UI。例：`reprokit ui`で`http://127.0.0.1:<port>`を開く。ネット上の共用サーバーで脆弱なLabを動かす設計にはしない。
- Webにしても**インストール不要にはならない**。Dockerの準備、ユーザーの実行権限、ブラウザ/ローカルバックエンドの安全性を考慮する。

### Webを採用する場合の必須事項

- ローカルサーバーは`127.0.0.1`のみにバインド。ランダムなセッショントークンを利用し、`Origin`検証とCSRF対策、Host検証（DNS rebinding対策）を実施する。
- Web経由で外部任意コマンドを実行させず、既存のManifest/Lockfile/Runtimeの安全性検査を**バイパスできない**APIを用意する。
- Web UIの画面は学習ガイドと起動状態を表示するが、`create`時に脆弱コンテナを自動起動しない。
- ラボのURLを外部公開しない。必要なら隔離VMを用いる。

## 最終決定で検証すべき点

初心者が初回のCVE学習を完了するまでの所要手順、つまずき、説明理解度、Docker前提による離脱率、実装・保守コストを小さなプロトタイプで比較する。

**注意：教育中心という製品方針は確定。Web/CLIの選択はこの資料では確定しない。**
