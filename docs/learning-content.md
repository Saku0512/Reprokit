# Reprokit 学習コンテンツ設計方針

> **教育を主軸にすることは決定済み。** Lessonの厳密なJSON Schema、ファイル名、コマンドやUIは今後決定する。この文書は教材に必須の品質要件を定義する。

## 教材作成の優先方針（2026-10-15）

**Vulhub（https://github.com/vulhub/vulhub）の既存検証環境と再現手順を教材の元資料として使用する。** Reprokitが重点を置くのは、脆弱性の日本語解説、初心者向けの段階的なPoC演習、観察結果の読み方、根本原因と修正方法。Webの学習画面が主役となる（[MVP仕様](vulhub-learning-mvp.md)）。

PoCは学習者自身が**ローカルの承認済み検証環境で手動実行**する。原典を丸写しするだけでは教材とせず、各ステップの意味・ヒント・期待結果・片付けまで作る。必要に応じて上流のライセンスや画像・素材の権利条件を確認する。

## LabとLessonは独立

- **Lab**：固定したCVE検証環境。既存の`reprokit.yaml`で定義する。
- **Lesson**：そのLabを使って学ぶ内容。実験手順と理解のための解説を管理する。
- Labの`metadata.id`、CVE ID、Lesson ID、ローカルInstance IDを混同しない。
- 1 Labに複数Lesson（例：仕組みの初級編、修正方法を考える応用編）を持てる。
- あるLabが起動できる（Bootable）ことと、その教材を修了したことは**別の状態**とする。

## 教材に必要な要素

| 要素 | 内容 |
| --- | --- |
| ID・題名 | 固有の教材識別子とわかりやすい日本語のタイトル |
| 対象 | 対応CVE、紐付くLab ID |
| 学習レベル | 初級・中級・上級の区分、必要な前提知識 |
| 学習目標 | 終了後に何を説明・実演できるか |
| 事前説明 | CVEの概要、根拠、影響範囲、対象環境での制限 |
| 演習手順 | **学習者自身がローカルLabでPoCを実行するための**段階的な操作、コマンド例・コピー、各段階で期待する観察 |
| ヒント | 自分で考えるための補助。最初から全解答を表示しない |
| 振り返り | なぜ発生したか、影響範囲、修正・緩和方法 |
| 片付け | 停止・削除の導線、注意点 |
| 出典 | CVEレコード・ベンダー・修正差分など。更新日や対応バージョンを明記 |

## 教材品質の条件

- 重要な用語は初出時に説明し、成功時・失敗時に何を確認すべきかを書き分ける。
- 「この手順はローカル検証環境のみ対象」「実運用システムへ試さない」を明確にする。
- CVEと学習内容の対応を人間がレビューする。CVE番号だけから自動生成した説明を**検証済み教材**として掲載しない。
- 原則、日本語を第一言語とし、原典への英語リンクは残す。
- **環境構築に成功しただけでは修了としない。** 実際の観察・理解・対策の説明が必要。
- まず1～3教材で初心者テストを実施してから種類を増やす。

## 学習体験の試験項目

1. その教材の前提知識を読めば、何をするのかわかる。
2. 環境準備中の失敗を自分で説明・対処できる。
3. 期待する観察結果を確認できる。
4. 発生原因と対策について自身の言葉で説明できる。
5. 不要になった環境を安全に停止・削除できる。
